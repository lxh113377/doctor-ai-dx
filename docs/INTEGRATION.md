# 集成契约（对接方读这一页）

> 定位：给"要把本系统接进 HIS/公卫平台/自建 Agent 的工程师"看的决策页。`docs/OPENAPI.md` 讲**请求长什么样**，本页讲**在什么档位上可用、什么时候不该等你、我方永远不会给什么**。
> 口径纪律：本页不抄任何时延/条数读数，一律指向唯一源（见每节末「读数源」）。抄了就必然过期，这是本仓 #106 立过的同族事故。

## 1. 三个调用档位（先选档，再看接口）

| 档位 | 同步预算 | 我方链路是否可达 | 建议用法 |
|---|---|---|---|
| 同步阻塞在医生操作路径上（如处方签发时的即时拦截） | 行业惯例是"秒级以内"，HL7 CDS Hooks 写的建议值是 500ms 量级 | **不可达**。大模型链路一次的读数就远超该档（读数源：`docs/EVAL_CARD.md` 现役行，由脚本从当日线上报告生成） | 不要把我方 `/api/dx` 放进签发事务的关键路径 |
| 页面加载后异步出提示（打开患者视图后再补一张建议卡） | 秒级～十秒级，允许先出骨架再补内容 | **可达**，这是本系统的设计用法；约束与实测口径见 `docs/EVAL_CARD.md` | 前端先渲染占位，回来再填诊断/检查建议/引用 |
| 离线/无密钥（断网、评审现场、自托管试用） | 零外呼 | **可达**，全链路降级为确定性规则模板并如实标 `mode=rule-fallback` | 见 `docs/ERRORS.md` 与 `docs/PRIVACY.md` §7 |

**结论一句话**：把本系统当"随诊参考专家"接（异步、可缺、由医生终审），不要当"事务内联拦截器"接。

## 2. 失败语义（我方是 fail-closed 到规则档，不是 fail-open）

- 模型侧任何失败（无密钥/超时/网络/HTTP 错误/非法 JSON/schema 漂移/空输出/截断/内容过滤/未知完成态）都**收敛到同一条出口**：确定性规则结果 + `fallback_reason` 文案 + `fallback_cause` 闭集枚举。原因枚举的唯一源是 `frontend/tests/fixtures/llm_fallback_causes.json`，两端各自对账它。
- 当前实现**单次调用、零重试、无熔断**（行为回执：`frontend/tests/live_path_guard.mjs` 的失败路径断言同时核外呼次数）。集成方若要重试/退避，请在自己这侧做幂等重试——我方链路无密钥时零外呼，重复请求不产生副作用，但也不产生新的诊断依据。
- 红旗规则层的命中**不受降级影响**：模型失败时红旗照常输出，且模型无法覆盖它（红线一，常驻判据同文件）。
- 对外错误文案只给医生能读懂的话 + 故障编号，不吐堆栈与内部路径（`docs/ERRORS.md`）。

## 3. 引用与出处的可对接形状

- 每条诊断/建议带 `refs`，与 `evidence_ids` 一一对应；**未过白名单的 id 一律剔除**（白名单只证"该条目在知识库内在场"，不证该条正文支撑这句结论）。逐例支撑强度测量在 `frontend/tests/grounding_ruler.mjs`，读它给的下钻数而不是读本页。
- 出处字段目前到"指南名 + 年份 + 域名"层级，**没有**每条的深链（现状与缺口见 `docs/EVAL_CARD.md` 的溯源段与台账 #203/#207）。要接进需要 CDP/Citation 级出处的系统，先按"部分满足"评估，别把本页当合规声明。
- 若对接 HL7 CDS Hooks：本系统的规则层天然对应 `card` 的 `indicator=critical` + `source.label`，但标准**不提供**"禁止人类覆盖"的字段（它只标准化 override 的记录），也不提供比 `source.label/url/topic` 更结构化的证据引用。所以我方"模型不可覆盖红旗"仍是**内部不变量**，不是协议能力。

## 4. 我方永远不会给的东西（避免接了才发现）

- 不做认证/授权与多租户；不做任何患者数据持久化（零落库，见 `docs/PRIVACY.md`）。
- 不做医疗器械注册、HIPAA/GDPR/等保主张；定位是教学与竞赛原型（`LICENSE`）。
- 不解读影像/报告单、不给剂量、不面向动物患者（`data/scope_rules.json` 逐条附理由）。
- 不给真实世界准确率：所有评测数字是"自建病例 → 自建知识库 → 引擎排序"的三者自洽度（`docs/EVAL_CARD.md` 每行带口径限定）。

## 5. 接入前置检查清单

1. 跑一次 `npm run test:contract` 与 `npm run test:api` 确认你手上的响应形状与仓内一致（两端镜像面同源）。
2. 用 `GET /api/health` 判定当前是 live 还是无密钥降级，不要假设。
3. 异步调用方必须处理"结论缺但红旗在"的形态：红旗字段独立于 `mode`，缺结论时红旗仍可能非空。
4. 把时延档位当成硬约束来测：用你自己那侧的计时，把读数与本仓的 P95 口径（同 mode 内才可比）对齐后再决定放在哪条链路上。
